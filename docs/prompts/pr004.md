# Bug Report: "Huy Luot Tra Gia Cuoi" Button Behavior

## Overview
The "Huy Luot Tra Gia Cuoi" button currently exhibits incorrect behavior in two scenarios:
1. It is always enabled, even when the selected bidder is not the last one.
2. It becomes enabled immediately after use, allowing repeated actions without new bids being placed.

This document outlines the expected behavior, implementation requirements, and additional notes to address these issues.

---

## Issues and Expected Behavior

### Issue 1: Button Enabled for Non-Last Bidders
#### Current Behavior
- The button is always enabled, even when the selected bidder is not the last one.

#### Expected Behavior
- The button should only be enabled when:
  1. A bidder is selected.
  2. The selected bidder is the last bidder.
  3. There are existing bids.
- If no bids exist, the button should remain disabled.

---

### Issue 2: Button Re-Enables After Use
#### Current Behavior
- After clicking the button, the last bid is removed, and the button is immediately enabled for the next last bidder.

#### Expected Behavior
- After clicking the button, it should remain disabled until a new bid is placed.
- This ensures the button cannot be used repeatedly without new bids being added.

---

## Implementation Requirements

### State Management
- Use explicit state management to control the button's enabled/disabled state.
- Persist the button state using local storage or a global state management library to ensure consistency across transitions.
- Do not rely on intermediate logic to maintain the button's disabled state.

### Transition Behavior
- When transitioning from the setup page to the bid page:
  - The button should always be disabled by default.
  - The button state should persist across transitions to reflect the correct behavior.

### Bidder Selection Logic
- The button should only be enabled when:
  1. A bidder is selected.
  2. The selected bidder is the last bidder.
  3. There are existing bids.
- The button should remain disabled when:
  1. No bidder is selected.
  2. The selected bidder is not the last bidder.
  3. There is no new bid since the last button click.
  4. The auction has ended.

### Post-Cancellation Behavior
- After the button is clicked:
  1. The selected bidder should be cleared.
  2. The last bidder should be updated to the previous bidder (if any).
  3. The button should remain disabled until a new bid is placed.

---

## Additional Notes
- Provide clear user feedback (e.g., toast messages) to indicate why the button is disabled or enabled.
- Test all edge cases, including:
  - No bids exist.
  - The auction has ended.
  - A new bid is placed after cancellation.
- Ensure the button state is properly managed during transitions between setup and bid pages.
- Document the logic for button state management to ensure maintainability.
